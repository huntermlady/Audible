### 4.1 Column details not fixed by §5.2
- Integer columns (season, week, down, plays, games, counts, ranks): int32 in parquet. Rates and EPA: float64. `is_home`, `low_sample`: bool. Everything else: string.
- `team_season` `rank_<metric>`: one for every numeric metric column **except** `season, games, off_plays, def_plays`. The direction follows CONTEXT.md. Rank is null on `NFL` rows and when the metric is null. Ties use `min` rank.
- `team_tendencies.cell_key` formats (values use `_`; the separator is `-`; never `.`):
  - `overall` → `all`
  - `down_dist` → `d{down}-{dist_bucket}` (e.g. `d3-long`)
  - `down_dist_zone` → `d{down}-{dist_bucket}-{field_zone}`
  - `zone` → `{field_zone}`
  - `score_time` → `{score_state}-{time_bucket}`
  - `down_dist_score_time` → `d{down}-{dist_bucket}-{score_state}-{time_bucket}`
- `down` in tendencies: 1–4. Down 4 rows exist; plays exclude punts and FGs, per CONTEXT.md.
- `NFL` rows in team_tendencies have `side` = `off` only (league offense = league defense allowed). `NFL` rows in team_season contain both off_ and def_ columns (they are equal where symmetric).
- `schedule.json` covers every season in `manifest.seasons`, including future games (scores null).
- `manifest.current_week` = the **upcoming** week: the smallest week of `current_season` that has an unplayed game. After the Super Bowl, it is the last week.

## 6. Fact sheet rules fixed here (T2 elaborates in `shared/factsheet/SPEC.md`)
- Facts come **only** from `team_tendencies` rows. `league_value` comes from the `NFL` row with the same season/grouping/cell_key/metric (side `off`).
- Stat ID: `{team}.{side}.{season}.{grouping}.{cell_key}.{metric}` where metric = a tendency column name.
- `unit` ∈ `rate | epa | count | yards`. `display`: rate → integer percent `"41%"`; epa → signed 2 decimals `"+0.12"` / `"-0.05"` (`"0.00"` for zero); count → integer `"58"`; yards → 1 decimal `"8.4"`. The same format applies to `league_display`.
- Null metrics are omitted (never emitted as a fact). There are at most 40 facts. Facts are ordered deterministically (the spec defines the order). The JSON is not serialized with sorted keys. Keys follow the schema's property order. Floats are rounded to 4 decimals in `value`. Py and TS must produce byte-identical `JSON.stringify(obj, null, 2)` / `json.dumps(obj, indent=2, ensure_ascii=False)` output.
- Matchup context: `{"kind":"matchup","game_id":…,"season":…,"team":…,"opponent":…,"role":"OC"|"DC"}`. Situation context: `{"kind":"situation","situation":{…}}`.

## 8. Web: Track 2 → Track 4 AI API (`@/ai`, barrel `web/src/ai/index.ts`)
```ts
buildFactSheet(ctx: FactSheetContext, tables: { tendencies: TeamTendencyRow[] }): FactSheet   // pure; byte-identical to Python

runCoordinatorCall(args: { situation: Situation; tendencies: TeamTendencyRow[]; provider: Provider; signal?: AbortSignal; onToken?: (t: string) => void })
  : Promise<{ ok: true; call: CoordinatorCall; factSheet: FactSheet; attempts: number; latencyMs: number; firstTokenMs: number | null }
          | { ok: false; errors: string[]; factSheet: FactSheet; attempts: number }>   // 1 retry with errors appended; throws AbortError on cancel
buildChatSystem(ctx: ChatRequest['context'], fs: FactSheet | null): string
chatFactSheetContext(ctx: ChatRequest['context'], season: number): FactSheetContext | null
AIStatusProvider, useAIStatus(): { status: 'checking'|'live'|'sample'|'error'; provider: Provider | null; settings: { baseUrl: string; model: string }; setSettings(s): void; retry(): void; errorHint?: string }
type Provider  // per BUILD_PLAN §5.4
```
- `useAIStatus` does the 1.5 s `/api/tags` probe. Settings persist in localStorage under `audible.ai.settings` (in try/catch). `errorHint` explains a blocked HTTPS-to-localhost request (the page is served over https and fetch fails with a TypeError): "use `make preview` for live mode".
- The Claude dev adapter is imported only under `if (import.meta.env.DEV)` through a dynamic import, so production builds tree-shake it. It calls `/__claude` on the Vite dev server. T3 adds the dev-only proxy middleware in `vite.config.ts`, which reads `ANTHROPIC_API_KEY` from `.env` on the server side. **T2 specifies the request/response shape of `/__claude` in `docs/HANDOFFS.md`, and T3 implements it.**
