2026-09-25 [T2→T3] **`/__claude` dev-proxy spec** (implement in `vite.config.ts`, `apply: 'serve'` only; never in build/preview):
- `POST /__claude` with `Content-Type: application/json`. The body is an Anthropic Messages API request body that T2's `claude-dev` adapter builds: `{ model, max_tokens, system, messages, stream: true, output_config? }`.
- The proxy reads `ANTHROPIC_API_KEY` from `.env` on the server side (Vite `loadEnv(mode, root, '')`; never through a `VITE_` prefix). Then it:
  1. Rejects anything that is not POST with `405`. It rejects a body where `typeof model !== 'string' || !model.startsWith('claude-')` or `max_tokens > 8192` with `400` and `{"error":{"type":"invalid_request","message":"…"}}`.
  2. When the key is missing, it responds `503` with `{"error":{"type":"missing_key","message":"ANTHROPIC_API_KEY is not set in .env"}}`.
  3. Otherwise it forwards the body unchanged to `https://api.anthropic.com/v1/messages` with headers `x-api-key: <key>`, `anthropic-version: 2023-06-01`, and `content-type: application/json`.
  4. It pipes the upstream **status code** and **body** back unchanged, streaming them without buffering, and copies upstream `content-type` (`text/event-stream` on success, JSON on error). Flush each chunk as it arrives.
- It never logs the key or echoes request headers back. T2's Vitest grep test fails the build if `__claude`, `claude-dev` or `ANTHROPIC` appears in `web/dist/`, so keep the middleware in `vite.config.ts` or `vite-plugins/`, not under `src/`.
